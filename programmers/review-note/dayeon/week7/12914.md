## [`12914`: `멀리 뛰기`] 

### 사용했던 방식 및 알고리즘
- DP(Dynamic Programming) 중 **타뷸레이션(Bottom-up)** 방식
- 1차원 배열 `f[]`에 이전 두 값(`f[i-1]`, `f[i-2]`)을 저장해두고 반복문으로 누적 계산
- 오버플로우 방지를 위한 나머지 연산(`% 1234567`) 적용
### 해결이 안 됐던 점
- 코드 전체 흐름(배열이 어떤 순서로 채워지는지)이 한눈에 안 들어옴
- DP라는 개념 자체의 정의(중복 부분 문제 저장 + 최적 부분 구조)가 명확히 안 잡힘
- 메모이제이션(Top-down)과 타뷸레이션(Bottom-up)의 차이/이름을 헷갈림
### AI 및 구글링에서 알려준 방식 및 알고리즘
```java
int[] f = new int[n + 1];
f[1] = 1;
f[2] = 2;
 
for (int i = 3; i <= n; i++) {
    f[i] = (f[i - 1] + f[i - 2]) % 1234567;
}
return f[n];
```

### DP의 기본 유형
```java
int [] dp = new int[n+1];
dp[0] = 1;
dp[1] = 2;
for(int i = 1; i<=n; i++){
    dp[i] = f(dp[i-1],dp[i-2],..)//점화식
    }
    return dp[n]
```  

**알고리즘 설명**
피보나치 점화식(`f[i] = f[i-1] + f[i-2]`)을 배열에 작은 인덱스부터 순서대로 채워나가는 Bottom-up DP. 매번 재귀로 다시 계산하지 않고 배열에 값을 저장해서 재사용하기 때문에 O(n) 시간에 해결 가능.

### 반복적으로 어려워하는 패턴 (관찰)
- 코드를 볼 때 "왜 이렇게 짜여있는지" 큰 그림보다 세부 문법 먼저 파고드는 경향
- 비슷한 개념 두 개가 붙어 나오면(Top-down/Bottom-up처럼) "이게 그거 맞아?" 식으로 확인 질문을 여러 번 반복
- 아직 첫 기록이라 데이터가 적음 → 문제 몇 개 더 쌓이면 이 패턴이 진짜 반복되는지 확인 필요
