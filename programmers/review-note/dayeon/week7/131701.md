## [`프로그래머스`: `연속 부분 수열 합의 개수`]

### 사용했던 방식 및 알고리즘
- `HashSet`을 사용해서 중복되는 합을 제거했다.
- 원형 수열을 처리하기 위해 기존 배열 길이의 2배인 `extended` 배열을 만들었다.
- `elements[i % n]`을 사용해서 원래 배열을 한 번 더 이어 붙인 것처럼 만들었다.
- 부분 수열의 길이를 `1`부터 `n`까지 바꿔가며 모든 연속 부분 수열의 합을 구했다.
- 구한 합을 `set1`에 저장한 뒤, 마지막에 `set1.size()`를 반환했다.

### 해결이 안 됐던 점
- 원형 수열을 어떻게 코드로 표현해야 하는지 헷갈렸다.
- `elements[i % n]`이 왜 배열을 반복해서 접근하게 해주는지 이해하지 못했다.
- 3중 반복문에서 `i`, `j`, `k`가 각각 무엇을 의미하는지 구분하지 못했다.
- `HashSet`을 사용하는 이유가 “모든 합의 개수”가 아니라 “서로 다른 합의 개수” 때문이라는 점을 놓쳤다.

### AI 및 구글링에서 알려준 방식 및 알고리즘
```java
Set<Integer> set1 = new HashSet<>();
int n = elements.length;

int[] extended = new int[n * 2];

for (int i = 0; i < n * 2; i++) {
    extended[i] = elements[i % n];
}

for (int i = 1; i <= n; i++) {
    for (int j = 0; j < n; j++) {
        int sum = 0;

        for (int k = 0; k < i; k++) {
            sum += extended[j + k];
        }

        set1.add(sum);
    }
}

return set1.size();
```


알고리즘 설명
이 문제는 원형 수열에서 만들 수 있는 연속 부분 수열의 합 중, 서로 다른 값이 몇 개인지 구하는 문제다.
원형 수열은 마지막 원소 다음에 다시 첫 번째 원소가 이어지는 구조다.
원형 구조를 쉽게 처리하기 위해 원래 배열을 두 번 이어 붙인 extended 배열을 만든다.

```
예시:
elements = [7, 9, 1, 1, 4]

extended = [7, 9, 1, 1, 4, 7, 9, 1, 1, 4]
elements[i % n]을 사용하면 인덱스가 배열 길이를 넘어가도 다시 처음부터 접근할 수 있다.

예시:
i = 0 -> elements[0 % 5] -> elements[0]
i = 1 -> elements[1 % 5] -> elements[1]
i = 2 -> elements[2 % 5] -> elements[2]
i = 3 -> elements[3 % 5] -> elements[3]
i = 4 -> elements[4 % 5] -> elements[4]
i = 5 -> elements[5 % 5] -> elements[0]
i = 6 -> elements[6 % 5] -> elements[1]
```
3중 반복문에서 각 변수의 의미는 다음과 같다.
i = 부분 수열의 길이, 즉 몇 개를 더할지
j = 부분 수열이 시작하는 위치
k = 시작 위치에서 몇 칸 이동해서 더할지
```
예를 들어:
extended = [7, 9, 1, 1, 4, 7, 9, 1, 1, 4]
i = 3
j = 4
이면 j = 4번 위치부터 i = 3개를 더한다.
k = 0 -> extended[j + k] = extended[4 + 0] = extended[4] = 4
k = 1 -> extended[j + k] = extended[4 + 1] = extended[5] = 7
k = 2 -> extended[j + k] = extended[4 + 2] = extended[6] = 9
```
따라서 합은 다음과 같다.\
```4 + 7 + 9 = 20```\
HashSet은 중복된 값을 저장하지 않는다.\
문제에서 원하는 것은 연속 부분 수열 합의 전체 개수가 아니라, 서로 다른 합의 개수다. \
따라서 모든 합을 HashSet에 넣고 마지막에 set1.size()를 반환하면 된다.
```
set1.add(sum);
return set1.size();
```

시간 복잡도는 3중 반복문이므로 대략 O(n^3)이다.
다만 이 문제에서 elements의 길이가 크지 않다면 이 방식으로도 이해하기 쉽다.
