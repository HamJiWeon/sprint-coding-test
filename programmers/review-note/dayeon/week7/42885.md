## [`42885`: `구명 보트`] 

### 사용했던 방식 및 알고리즘
- 정렬 + **투 포인터(Two Pointer) 그리디**
- `min`(가장 가벼운 사람), `max`(가장 무거운 사람) 두 포인터를 양 끝에서 좁혀가며 비교
- 본인이 작성한 코드 자체는 정답 (로직은 맞았음)
### 해결이 안 됐던 점
- 코드는 정확히 짰지만 "왜 이렇게 동작하는지" 원리를 이해하지 못함
- 특히 `max--`는 매번 무조건 실행되고 `min++`는 조건부로만 실행되는 이유가 헷갈림
- "가장 무거운 사람은 가장 가벼운 사람하고만 비교해도 충분하다"는 그리디적 증명이 바로 와닿지 않음
### AI 및 구글링에서 알려준 방식 및 알고리즘
```java
import java.util.Arrays;
class Solution {
    public int solution(int[] people, int limit) {
        int answer = 0;
        Arrays.sort(people);
 
        int min = 0;
        int max = people.length - 1;
 
        while (min <= max) {
            if (people[min] + people[max] <= limit) {
                min++;
            }
            max--;
            answer++;
        }
        return answer;
    }
}
```

**알고리즘 설명**
정렬 후 가장 무거운 사람(max)은 이번 턴에 반드시 보트를 탄다(혼자 타든 min과 같이 타든). max가 지금 남은 사람 중 제일 무거우므로, min과도 못 타면 다른 누구와도 못 탄다 → 그래서 max는 min하고만 비교해봐도 충분. 같이 탈 수 있으면 min도 함께 소진(min++), 아니면 max 혼자 소진. 매 반복마다 보트 1개(answer++) 사용. O(n log n)으로 해결.

### 반복적으로 어려워하는 패턴 (관찰)
- 코드는 정확히 구현했지만, 그 이면의 **그리디 증명("왜 이 비교만으로 충분한가")**을 스스로 설명하지 못하는 경향
- 두 포인터가 "대칭적으로" 움직이지 않고 한쪽만 조건부로 움직이는 구조(비대칭 투 포인터)에서 혼란
